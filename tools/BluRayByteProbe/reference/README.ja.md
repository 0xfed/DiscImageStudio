# 独立した 17PP 参照実装

[简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [English](README.md) | [日本語](README.ja.md) | [Türkçe](README.tr.md)

ユーザー提供の ISO/IEC 30190:2021 の §13.17 と図 41 から転記した、Python 標準ライブラリによるツールです。この実装は製品用の C# エンコーダーをインポートしません。有限長の参照実装は、4 バイト反復入力 256 種すべてと有限ビットパターンベクトル 298 個について C# と照合し、すべて一致しました。出力成果物には期待されるベクトルも含まれます。

リポジトリのルートから実行します。

```powershell
python tools/BluRayByteProbe/reference/analyze.py --output-dir artifacts/bluray-byte-density/reference
python tools/BluRayByteProbe/reference/pattern_search.py --output-dir artifacts/bluray-byte-density/reference
python tools/BluRayByteProbe/reference/robust_pattern_search.py --output-dir artifacts/bluray-byte-density/reference
```

`--output-dir` の既定値は現在のディレクトリです。両方のパターン探索は `--max-period`（既定値 16）を受け付けます。外部の Python パッケージは不要です。

3 つの Python ツールのヘルプ、進捗、エラー、JSON の説明文は 5 言語に対応し、`--language zh-CN|zh-TW|en|ja|tr|system` と `DISC_IMAGE_STUDIO_LANGUAGE` を共用します。明示的なオプションが優先し、指定がなければシステム UI 言語に従います。言語を選択しても、フィールド名、CSV 列、厳密な比率、ビット列、数値解析は保持されます。参照アルゴリズムは引き続き C# エンコーダーから独立しています。

```powershell
python tools/BluRayByteProbe/reference/analyze.py --language ja --help
```

## 測定領域

対象は、明示的にモデル化された DC 挿入の前にある、**17PP 入力端でのスクランブル後の入力**です。生のホストペイロードパターンではありません。密度は変調ビットの 1 の数をチャネルビット数で割った値です。変調ビットが 1 であるたびに NRZI 記録レベルが反転します。*変調ビット間*の変化を数えると、別の量を測定することになります。

`analyze.py` は、直前の変調ビットの両方の値から開始し、各反復バイトと入力ビット位相 8 種すべてについて正確な反復サイクルを計算します。バイト結果を JSON/CSV に保存し、4 バイトの有限ベクトルも保存します。基準には EDC、RS パリティ、LDC インターリーブ、BIS、同期、DC ビットは含めません。固定 DC 結果では、ソースビット 45 個ごとに制御ビットを 1 個、無期限に挿入します。これは感度診断であり、規格に適合する完全な記録フレームや DC 平衡済み出力ではありません。

`pattern_search.py` は、直前の変調ビットの両方の値を使用し、長さ 2～16 の全 131,068 個の 2 進文字列を明示的に評価します（正確なサイクル評価 262,136 回）。入力 2 ビット単位の回転と直前ビットの選択に対して密度が不変であることを検証し、対応する 14,694 個の回転クラスに分類します。奇数周期には回転軌道が 1 つあり、偶数周期では奇数／偶数のアラインメントクラスを分けて保持します。長さごとの極値の報告には、等価パターンや短いパターンの反復も含めるため、ここでいう長さは周期の長さであり、必ずしも最小周期ではありません。

`robust_pattern_search.py` は全ビット回転をまとめ、ビット対の両位相を比較します。**探索した周期長の範囲内で**、位相に頑健な最小値の最良値は 1/6、最大値は 4/9 です。この 2 つの頑健な結果が、より長い周期に対する大域的な限界であるとは主張しません。

NRZI のレベル 1 占有率は初期レベルをゼロとして求めます。初期レベルを反転すると占有率は補数になります。デューティ比 50% から、光学的な結果が黒か白かを予測することはできません。

## 到達可能なチャネル密度の限界

任意に長い 17PP 変調データ区間では、各ランは最大 8T であるため、遷移密度は少なくとも 1/8 です。16 ビット入力サイクル `0000101101110010`（`0B 72` の反復）は、出力サイクル `000100000001000000010000`、すなわち 8T のラン 3 個により、この限界を達成します。

反対側の極値では、2T のランが連続するのは最大 6 個です。最大 6 個の 2T ランの列を、その次にある少なくとも 3T のランと組にすると、密度は最大 7/15 になります。10 ビット入力サイクル `0111011110`（`77 9D E7 79 DE` の反復としてパック）は、出力サイクル `101010101001010`、すなわち 2T のラン 6 個と 3T のラン 1 個によってこれを達成します。これらは実際にテーブルから生成されたサイクルであり、単なる RLL の限界ではありません。両極値とも、完全なレベルサイクルでの NRZI 占有率は 50% です。

これらの限界は長いデータ区間に適用されます。フレーム同期には特別な 9T のランがあり、通常の 17PP 規則の範囲外です。有限長の終端やその他の物理フレーム構成は、別に数える必要があります。

| 入力パターン | この位相でのパック方法 | 密度 | 出力サイクル内のラン | 奇数入力ビット位相 |
|---|---|---:|---|---:|
| `0001` | `11` の反復 | 1/6 = 16.6667% | 6T | 1/6 |
| `00111101` | `3D` の反復 | 5/12 = 41.6667% | 2T が 3 個 + 3T が 2 個 | 5/12 |
| `001111` | `3C F3 CF` の反復 | 4/9 = 44.4444% | 2T が 3 個 + 3T が 1 個 | 4/9 |
| `0000101101110010` | `0B 72` の反復 | 1/8 = 12.5% | 8T が 3 個 | 7/24 |
| `0111011110` | `77 9D E7 79 DE` の反復 | 7/15 = 46.6667% | 2T が 6 個 + 3T が 1 個 | 1/3 |

6 ビットの高密度候補では、DC 平衡前の NRZI デューティ比は極性によって 4/9 または 5/9 になります。DC 平衡によりこれは変わります。ビット対の位相に対する頑健性から、反復バイトの次に試す有用な候補になります。2 つの極端なパターンに無条件に DC ビットを挿入すると、有利なアラインメントが崩れます。

## 物理配置を通してパターンを保つ

有用な細粒度マッピングの一つは、制御可能な各ユーザービットを最終的な物理位置に基づいて選ぶ方法です。DC 挿入前のフレームビット索引 `j` に対し、その前に挿入される DC 位置の数は、`j < 25` のとき `0`、それ以外は `1 + floor((j - 25) / 45)` です。パターンビット `P[(j + dcBefore(j) + phase) mod period]` を選び、DC の挿入によって意図したパターンがずれないよう DC 位置を予約します。実際の DC 値は引き続きドライブが選び、隣接する符号語を変動させます。DC ブロックで位相をリセットする方法は、実験で比較する価値のある別の方式です。

この系列を記録フレーム／ECC バイト順に構成し、既存の LDC 順列の逆を使って、制御可能なユーザーバイトをスクランブル後のペイロードに配置します。対応するスクランブラーマスクを適用すると、ホストバイトを復元できます。ホスト順またはソースセクター順で反復したバイトパターンは、通常、インターリーブ後に周期性を保ちません。EDC、LDC パリティ、BIS、同期、DC の値は、独立に設定できるペイロードビットではありません。すべてのフレームビットを制御可能とみなさず、これらを全パイプラインの測定に含めてください。

密度も NRZI デューティ比も、最終的な黒白の極性を決めるものではありません。書き込んだパッチの反射率と可視性は、引き続き実測で確認する必要があります。
