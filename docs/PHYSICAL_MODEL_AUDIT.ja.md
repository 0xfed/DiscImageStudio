# CD / DVD 生成の物理モデルの再検証

[简体中文](PHYSICAL_MODEL_AUDIT.md) | [繁體中文](PHYSICAL_MODEL_AUDIT.zh-TW.md) | [English](PHYSICAL_MODEL_AUDIT.en.md) | [日本語](PHYSICAL_MODEL_AUDIT.ja.md) | [Türkçe](PHYSICAL_MODEL_AUDIT.tr.md)

検証日：2026-09-21。対象は、未コミットの校正実装を含む `DiscImageStudio-GitHub` の当時のワークスペースで、基準コミットは `6c55a18` です。今回は規格との照合、ソースコード監査、独立した数値検証のみを行い、生成器、プリセット、書き込み動作は変更していません。

## 結論

基本的な螺旋の式と DVD のセクター長に計算誤りは見つかりませんでした。ただし、現在のモデルでは、規格の公称パラメーターだけから実際の盤面の角度を正確に予測できません。既定の CD パラメーターには幾何学的な整合性の問題があり、線密度を固定した単一線による校正は密度誤差を半径に吸収します。また、CD インターリーブの有限ストリーム境界と参照タイミングは幾何モデルに含まれていません。書き込みメディアの種類と生成モデルの適合性チェックも不足しています。

この監査だけで、特定の実ディスク上の曲がりの唯一の原因を特定することはできません。また、DVD のビット長を別の公称値に直接変更することを修正とみなすべきではありません。

## 参照規格と適用範囲

- 公式の [ECMA-359 第 1 版、2004](https://ecma-international.org/wp-content/uploads/ECMA-359_1st_edition_december_2004.pdf)：単層 DVD-R。主に §§10.7–10.9、18–23、24.2 を確認しました。PDF の 28、29、52、56 ページの原ページを照合しました。
- 公式の [ECMA-267 第 3 版、2001](https://ecma-international.org/wp-content/uploads/ECMA-267_3rd_edition_april_2001.pdf)：DVD-ROM。主に §§10.6、18–21 を確認しました。記録可能メディアのすべての規則をこれで置き換えることはできません。
- 公式の [ECMA-130 第 2 版、1996](https://ecma-international.org/wp-content/uploads/ECMA-130_2nd_edition_june_1996.pdf)：CD-ROM の幾何と共通 CIRC 符号化の参照。§§8.6、11.3–11.4、19.4、附属書 C を確認しました。音声トラックは CD-ROM のデータトラックと同じではありません。
- 公式の [ECMA-394 第 1 版、2010](https://ecma-international.org/wp-content/uploads/ECMA-394_1st_edition_december_2010.pdf)：CD-R。多倍速記録、プリグルーブ、Red Book との互換性について、§§1.2、2.4–2.5 を確認しました。この文書は Red Book の参照により一部の幾何要件を定めており、CD の幾何表全体を直接再掲しているわけではありません。

ECMA-359 の主な制約は次のとおりです。すべて規格要件であり、特定のディスクの実測値ではありません。

| 項目 | 制約 | 条項 |
|---|---|---|
| データ開始半径 | 23.9–24.0 mm | 10.7.1.2。原文は直径 48.0 mm、公差 −0.2/+0.0 mm |
| 12 cm ディスクのデータ終端半径 | 58.0 mm 以下 | 10.7.1.2 |
| 平均トラックピッチ | 0.74 ± 0.01 μm | 10.8 |
| 局所トラックピッチ偏差 | 0.74 μm に対して最大 ±0.03 μm | 10.8 |
| 平均チャネルビット長 | 133.3 ± 1.4 nm | 10.9 |
| データ領域の先頭 PSN | 0x030000。物理セクターは隙間なく連続 | 24.2 |

ECMA-267 のデータ開始直径の下限は DVD-R と異なります。§10.6.1 は 48.0 mm、公差 −0.4/+0.0 mm です。両規格の開始位置の公差を混用してはいけません。

## 正しいと確認できた部分

DVD のセクターあたりのチャネルビット数は `13 × 2 × (32 + 1456) = 38688`、16 セクターの ECC ブロックあたり 619008 ビットです。`DvdEccBlockEncoder.cs:8` の値は正しく、セクターオフセット、同期フレーム、PO 行インターリーブに一般的な長さの計上漏れは見つかりませんでした。

現在のトラック長は次のとおりです。

```text
CD:  L = (N / 75) × v                         [mm]
DVD: L = N × 38688 × channelBitLengthNm × 10^-6 [mm]
```

`CdDiscParameters.cs:59–75` は等ピッチの面積近似を、`ArchimedeanSpiral.cs:33–70,115–120` は厳密な弧長を使用します。近似関係は `pitch = π(ro²−ri²)/L`、`θ = 2L(r−ri)/(ro²−ri²)` です。CD の近似と厳密な螺旋の全ディスクでの角度差は約 0.000135° で、目に見える顕著な曲がりを説明できません。DVD の厳密な弧長の逆算、ナノメートルからミリメートルへの換算、既定の画像座標の向きにも誤りは見つかりませんでした。

DVD-R の linking は、特定のインクリメンタル追記の場合に用いられます。§24.2 はセクターの連続性を明記しています。すべての ECC ブロックに一律に「隠れた隙間」を追加する根拠はありません。

## 発見 1：既定の 80 分 CD プリセットのパラメーターの組み合わせが不適切

`src/DiscImageStudio.Core/Presets/built-in-disc-presets.json:6–12` は 359849 セクター、24.5–56.8 mm、1200 mm/s を組み合わせています。実際の生成式から逆算すると次のようになります。

| プリセット | 暗黙のトラックピッチ（μm） |
|---|---:|
| 80 分 CD の既定値 | 1.432856 |
| 74 分 CD の既定値 | 1.548384 |
| Ritek 水色 CD の実測半径プリセット | 1.492598 |
| Verbatim CD の実測半径プリセット | 1.500257 |
| 12 cm DVD の既定値 | 0.739837 |
| Verbatim DVD-R の実測半径プリセット | 0.738304 |

ECMA-130 §11.3 のトラックピッチ範囲は 1.5–1.7 μm、§11.4 の基準走査速度範囲は 1200–1400 mm/s です。既定の CD80 の組み合わせを、この幾何範囲に適合する汎用の精密プリセットとすることは明らかにできません。24.5 mm の開始位置も、§8.6 のユーザーデータ領域の開始位置（24.8–25.0 mm）と直接同一視できません。

これはソフトウェアのパラメーターの組み合わせの検証であり、ユーザーの CD-R を不適合と判定するものではありません。実測と記されたプリセットも 1200 mm/s に固定されており、線密度も測定済みという意味ではありません。規格範囲に収めるためだけにユーザーの実測半径を勝手に変更してはいけません。

## 発見 2：規格の公差は描画に必要な累積角度精度を大幅に超える

`ImageTargetMapper.cs:58–77`、`FastDispersionImageWriter.cs:345–365` は、容量、2 つの半径、固定ビット長から一定ピッチを逆算します。DVD の既定パラメーターでは約 45956.06 周になります。規格は局所的なピッチ変動を認め、58 mm は上限値なので、これらの入力で構成できるのは初期モデルだけです。

数値感度（1 つの入力だけを変更し、ほかを固定したモデルの比較）：

- DVD のビット長を 10 ppm 変更すると、全ディスクの累積角度は約 165.44° 変化します。
- DVD のビット長を 133.33 から 133.3 nm に変更すると、累積角度は約 10.34037 周変化します。
- DVD の内半径または外半径を 0.001 mm 増やすと、累積角度は約 −201.76° 変化します。

これらはモデルの位相差であり、実ディスクで測定した誤差ではありません。133.33 nm は規格公差内にあり、133.3 nm もすべてのディスクの真の正確なビット長ではありません。公称値を無条件に置き換えると、生成結果が大きく変わる可能性があります。

## 発見 3：1 本の半径方向の線だけでは半径と線密度を独立に特定できない

`CalibrationTarget.cs:468–473` は線速度／ビット長を固定し、`CalibrationCrossFitter.cs:73` は 2 つの半径と全体の回転だけをフィッティングします。現在の手順は同心円の元半径との対応関係を使用しません。

独立した反例：生成モデルを DVD `(ri=24, ro=58, bit=133.33)`、実際のモデルを `(24,58,133.3)` と仮定します。フィット用ビット長を 133.33 に固定したまま、候補半径だけを約 `(24.00540257,58.01305620)` に変更し、全体の回転を調整すると、25–57 mm の範囲でほぼ完全に同じ曲線を再現できます（2049 点の厳密弧長計算で最大位相残差は約 2.04×10^-10 rad）。この候補は既定の ±0.02 mm の探索範囲内です。これは解析的に構成した候補の順方向検証であり、現在の最適化器が必ずこの候補を返すという主張ではありません。

したがって、低い残差は単にビット長誤差を半径誤差として説明している可能性があります。現在の機能でも有用な補償パラメーターは得られますが、結果は「線密度を固定する仮定の下での等価パラメーター」と理解すべきです。真の物理半径と密度を特定するには、元半径が既知の円環、既知のデータ位置、または独立した境界測定を追加する必要があります。フィット変数をもう 1 つ自由にするだけでは、情報不足は解決できません。

## 発見 4：CD インターリーブ補償には有限ストリーム境界効果があり、物理タイミングの原点は未検証

`CddaInterleaver.cs:8–16` の遅延表は ECMA-130 図 C.4 のデータ経路と一致しており、誤った二重インターリーブではありません。独立したラベルシミュレーションで、現在の補償後 PCM を標準の順方向 CIRC の 24 データ経路に通すと、10 セクターのテストで定常状態の 20856 データ位置はすべて一致しました。ただし、合成結果ではターゲットパターン全体が 111 フレーム遅れます。

次の 2 点は厳密に区別する必要があります。

- **確定した有限ストリームの現象：**初期化で 1332 個のゼロのプレースホルダーバイトが生成され、末尾 108 フレームに分散した 1332 個のターゲットバイトは出力されません。`CddaInterleaver.cs:46–55` の Flush はセクター末尾だけを処理し、全セクター入力時にリングバッファを排出しません。これはパターン境界に影響します。
- **条件付きの物理オフセット：**111 フレームは図 C.4 の参照タイミングでの合成遅延で、約 15.102 ms、1200 mm/s では約 18.122 mm の弧長です。書き込み経路のタイミング原点で相殺されない場合、角度差は半径によって変わるため、開始角だけでは解消できません。ATIP、INDEX 01、実ディスクのデータ開始位置との関係は未測定なので、実証済みの物理オフセットと直接主張することはできません。

`CdTrackGenerator.cs:229–246` はこのタイミングを含まない globalByte でサンプリングし、幾何校正もこの符号化段階を含みません。既存の互換性説明にも、プレビューは完全な CIRC/EFM を模擬しないと明記されています。端から端までの物理タイミング検証を追加する必要があり、同じモデルによる生成とプレビューの一致だけでは盤面位置の正しさは証明できません。

## 発見 5：書き込みメディアの種類がモデルと照合されていない

`WindowsImapiBurner.cs:151–166,377–390` は IMAPI 対応、未使用状態、容量だけを確認し、実際の物理メディア種類を照会しません。一方、生成器は単層 ID（`DvdDataFrameBuilder.cs:41`）と単層の一方向螺旋を使用します。

二層 DVD、DVD-RAM など異なる物理形式を事前に拒否する処理が不足しています。IMAPI があるメディアに書き込めても、現在の描画モデルが適用できるとは限りません。実際に書き込みを開始できるかどうかは装置と状態にも依存します。二層の層切り替え、第 2 層の方向とビット長はモデル化されていません。

Microsoft の [CurrentPhysicalMediaType](https://learn.microsoft.com/en-us/windows/win32/api/imapi2/nf-imapi2-idiscformat2data-get_currentphysicalmediatype) と [物理メディア列挙型](https://learn.microsoft.com/en-us/windows/win32/api/imapi2/ne-imapi2-imapi_media_physical_type) を使用して照合できます。

## 推奨する修正順序

1. プリセットに暗黙のピッチのチェックを追加し、規格の初期値、実測値、補償で得た値を区別します。既定の CD80 の組み合わせを優先します。開始・終了半径がどのデータ位置に対応するかを明確にし、描画の切り抜き範囲とトラックの基準点を分離します。
2. CD インターリーブ、トラック開始、書き込み経路を合わせたタイミングを確認し、その後、最終セクター数を変えずにサンプリングオフセットと先頭・末尾の処理を修正します。
3. 校正に独立した半径またはデータ位置の制約を追加します。実測残差に系統的な局所の曲がりが残る場合は、可変ピッチ／位相補正モデルを評価します。
4. 書き込み前に、実際のメディア種類と容量が選択したモデルに一致するか確認します。

今回は実ディスクへの書き込みや光学的な明るさの測定を行っていません。検証は規格原文と原ページ、式の再計算、厳密な螺旋の数値比較、パラメーターを識別できない反例、CIRC データ経路のラベルシミュレーションを含みます。これらを完全な光学シミュレーションや実ディスク精度の認証に相当すると主張するものではありません。

監査の再現資料はワークスペースのルートの `tmp/standards-audit/` にあります。`circ-audit.py`、`circ-audit-result.json`、`geometry-audit.py`、`geometry-audit-result.json` に加え、ユーザーが提供した 2 つの PDF の抽出テキストと主要な原ページを含みます。
