# 單層 BD-R：位元組與位元週期的跳變密度分析

2026-10-24。依據提供的 ISO/IEC 30190:2021，尤其是 13.15–13.18、Figure 40/41，並使用本專案的 EDC、擾碼、LDC/BIS、DC、17PP 編碼鏈進行數值實驗。僅考慮單層光碟。

**以總跳變密度為目標時：值得採用按位元建構的模式。** 最佳重複位元組基準在完整叢集中的密度約為 **19.20% / 38.61%**；考量實體交錯與 DC 區段邊界後，受測位元週期方案達到 **15.95% / 43.37%**。兩端密度差由 19.41 增至 27.42 個百分點，增加約 41%。這些是數位編碼結果，實體光碟反射亮度及黑白方向尚未確定。目前繪圖依使用者選擇採用下列 **3T / 6T 次數偏向**，而非此處的密度極端方案。

## 按 3T / 6T 次數接入繪圖

採用同為 958,272 個通道位元的完整叢集，統計相鄰 modulation ONE 之間完整間隔為 3T 或 6T 的**絕對次數**。mark 與 space 皆計入；這不是 NRZI 電位的工作週期，也不是目標 run 次數 / 全部 run 次數的排名。

| 預設圖片端 | 擾碼域 Q | 基準叢集目標 run 次數 | 目標 run 占比 | 四位址目標次數範圍 |
| --- | --- | ---: | ---: | ---: |
| 暗部（0–127），偏 3T | `AA` | 265,136 | 85.4164% | 264,946–265,186 |
| 亮部（128–255），偏 6T | `44` | 116,575 | 62.6862% | 116,470–116,659 |

兩者在基準 PSN `0x100000` 的全部 256 個重複位元組中分別取得最高目標次數。6T 占比最高的 `22` 為 62.7744%，但僅有 116,402 次 6T，次數少於 `44`，因此次數模式選擇 `44`。在 `0x100000`、`0x234560`、`0x6D3A00`、`0xCA73E0` 四個位址複核，`44` 的 6T 平均次數為 116,559.5，略高於 `11` 的 116,526.5 與 `22` 的 116,457；這不表示它在每個位址都最佳。

正式使用的 `BluRayRunLengthMapping` 以 128 為閾值選擇 `AA` / `44`，可反轉黑白方向；`BluRayImagePayloadMapping` 依圖片位置取樣，串流產生器抵消擾碼後輸出 host 酬載。圖片邊緣、EDC、ECC、BIS、DC 與同步會引入其他 run 長度，因此「偏向 3T / 6T」不等於純 3T / 6T。預設明暗分配是可反轉的影像慣例，並未作為實體光碟反射亮度的校準。

以上數值採用目前的貪婪 DC 診斷模型；原始次數見 `all-bytes.json` 的 `Cluster.RunCounts`。架構回歸測試透過完整 RUB 編碼驗證碟首、碟尾兩端的次數偏向，並檢查混合圖片的擾碼及 ECC 位置。命令列與用法見[藍光說明](ADDING_BLURAY.zh-TW.md)。

## 測量定義

- 跳變密度 = modulation ONE 次數 / 通道位元數。ONE 表示一次 NRZI 翻轉，不能以 NRZI 電位中 ONE 的比例取代。
- Q 是**擾碼後的目標酬載**。host 酬載應寫入 `Q XOR scramblingMask`；直接循環原始 host 位元組會失去目標模式。
- 純 17PP 結果不含 DC、ECC、BIS、同步；使用獨立標準表與有限狀態精確循環計算。
- 完整叢集由 65,536 個 host 位元組產生，統計 `496 × 1932 = 958272` 個通道位元，包含 EDC、LDC parity、BIS、DC、同步；不含 run-in/out/Guard3，但使用 run-in 結束時的電位與 DSV。
- 預設 PSN 為 `0x100000`，位址 flags 與 user control data 為零。候選另在 `0x234560`、`0x6D3A00`、`0xCA73E0` 驗證。
- 主要結果使用目前的貪婪 DC 診斷演算法：未來控制位元暫設為零。它不保證與燒錄器決策一致；全 0、全 1、固定種子隨機 DC 是額外敏感度實驗，並非實際燒錄處方。

## 全 256 位元組基準

連續重複一個 Q 位元組，在無 DC/ECC 的穩態下只有四種密度：

| 純 17PP 密度 | 位元組數 |
| --- | ---: |
| 1/6 = 16.6667% | 28 |
| 1/4 = 25% | 92 |
| 1/3 = 33.3333% | 100 |
| 5/12 = 41.6667% | 36 |

其中 **80 個位元組在奇數位元偏移後會改變密度等級**。DC 插位會改變兩位元解析相位，因此不能僅依此裸編碼表排名。

## 更細粒度的可達模式

17PP 依 2/4/6/8 個輸入位元的變長規則編碼，並涉及前一個調變位元及特殊替代規則。位元組是載體，不能當作獨立碼字處理。

| 原始週期位元串 | 週期長度 | 位元組打包示意 | 純 17PP 密度 | 穩態 run |
| --- | ---: | --- | ---: | --- |
| `0001` | 4 | `11` | 16.6667% | 全部 6T |
| `00111101` | 8 | `3D` | 41.6667% | 3 個 2T、2 個 3T |
| `001111` | 6 | `3C F3 CF` | 44.4444% | 3 個 2T、1 個 3T |
| `0000101101110010` | 16 | `0B 72` | **12.5%** | 全部 8T |
| `0111011110` | 10 | `77 9D E7 79 DE` | **46.6667%** | 6 個 2T、1 個 3T |

一般 17PP 資料區段的 run 為 2T–8T，且最多連續六個 2T。因此長資料區段的密度下界為 `1/8`，上界為 `7/(6×2+3)=7/15`；上述 16 位元與 10 位元模式分別達到兩者。同步包含 9T，不能將此界限直接套用於含同步的任意短視窗。

兩個極端週期在奇數位元相位會退化至 29.1667% / 33.3333%。6 位元 `001111` 的兩種相位皆為 44.4444%，但裸 NRZI 工作週期為 4/9 或其互補，須由 DC 控制平衡。在週期不超過 16 位元的搜尋中，它是奇偶相位皆穩健的最高密度模式。

打包示意只說明如何表示週期。**不能直接循環這些 host 位元組，也不能只按原酬載順序循環 Q 而忽略交錯。** 例如按酬載順序填入 6 位元週期 Q，完整叢集僅約 33.43–34.39%；依實體 ECC 順序排列才達到約 40.64–40.75%。

## DC 補償與完整叢集結果

每訊框 155 個 ECC 位元組共 1240 個原始位元；先有 25 個資料位元，隨後每 45 個資料位元插入一個 DC 位元，共 28 個。令 `j=8×EccColumn+bitWithinByte`，其中 bit 0 為 MSB：

```text
DCbefore(j) = j < 25 ? 0 : 1 + floor((j - 25) / 45)
```

預留 DC 槽位：

```text
index = RecordingFrame × 1268 + j + DCbefore(j)
Qbit = pattern[(index + phase) % period]
```

依 DC 資料區段重新開始：

```text
index = j < 25 ? j : (j - 25) % 45
Qbit = pattern[(index + phase) % period]
```

插入 DC 後，每段起點皆位於偶數輸入位元，重新開始週期可保持兩位元解析相位。預留槽位方案僅保留位置，DC 位元值仍由編碼器／燒錄器選擇。EDC、BIS、parity 也不能任意控制，維持正常產生。

依這些實體位置建構 Q 後，反向散布至對應酬載位元組，再抵消擾碼。專案既有 `Map(luminance, position)` 已提供 RecordingFrame/EccColumn；每次呼叫中逐位元產生 8 位元即可，不必將回傳值限制為固定位元組。

| 推薦位元模式 | 建構 | 相位 | 完整叢集貪婪策略 | 四 PSN 範圍 | 另三種 DC 策略範圍 |
| --- | --- | ---: | ---: | ---: | ---: |
| 16 位元 `0000101101110010` | DC 區段重新開始 | 2 | **15.9500%** | 15.9405–15.9500% | 15.9278–17.0720% |
| 6 位元 `001111` | 預留 DC 槽位 | 3 | **40.8172%** | 40.8158–40.8315% | 41.0010–41.4603% |
| 10 位元 `0111011110` | DC 區段重新開始 | 4 | **43.3670%** | 43.3662–43.3713% | 42.1870–43.3904% |

相位從 0 開始，表示加在上式座標上的週期偏移。每個叢集從座標原點重新開始；這些相位僅針對此建構方式，不是將整體實體訊號任意移動相同位元數。

6 位元方案所有相位的完整叢集密度為 40.7929–40.8172%，相位變化影響較小。極端 16/10 位元方案仍須保持選定相位；相位錯誤可能回到約 30%–32%。DC 敏感度區間僅為這幾種已測策略的範圍，不是任意燒錄器的保證區間。

推薦低密度模式中，完整跳變間 run 的 **52.65% 為 8T**；推薦高密度模式中 **79.14% 為 2T**。這比只看平均密度提供更具體的實體光碟對照。兩者在貪婪模型中的 NRZI 電位占比皆約 50%，因此不能將位元值 0/1 直接解釋為視覺黑白。

## 首輪實體光碟候選

建議在相同光碟、燒錄速度與觀察條件下比較下列純色區塊，並在內、中、外半徑重複排列：

1. 稀疏端：16 位元週期、DC 區段重新開始、相位 2。
2. 高密度端：10 位元週期、DC 區段重新開始、相位 4。
3. 穩健高密度對照：6 位元週期、預留 DC 槽位、相位 3。
4. 位元組基準：`09`、`11`、`9E`；`00` 可另作一般輸入對照。

先以大區塊比較實際明暗與轉動觀察角度後的穩定性，再做區域混合與圖片映射。直接逐位元組交替兩種模式會改變編碼上下文，不應假設密度或亮度是兩端的線性平均。這些密度極端候選尚未進行實體光碟燒錄，也未用於目前預設黑白映射。

## 驗證與重現

- 獨立 Python 實作依標準 Figure 41 轉錄；與 C# 的 256 個四位元組向量、298 個週期向量逐位元一致。
- 窮舉長度 2–16 的全部 131,068 個原始位元串，各檢查兩種前置位元，共 262,136 次精確循環計算；驗證 14,694 個兩位元旋轉等價類。上述相位穩健最佳性僅限於此搜尋範圍。
- 完整鏈掃描全部 256 個位元組；合成訊框另檢查每位元組 8 種 DC mask × 31 種同步位置 × 2 種前訊框 termination。
- 細模式共 176 個模式／配置／相位組合，另做 120 個位址複核叢集。每個叢集皆驗證 65,536 個可控 Q 位元組在真實 ECC 位置與目標一致。
- 叢集長度、run 次數守恆與 RLL 間隔檢查通過；快速叢集掃描與完整 RUB 路徑相互一致。純資料沒有 2T–8T 以外的完整 run；含同步的叢集允許 9T。
