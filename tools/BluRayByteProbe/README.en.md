# Blu-ray byte and bit-period density analysis

[简体中文](README.md) | [繁體中文](README.zh-TW.md) | [English](README.en.md) | [日本語](README.ja.md) | [Türkçe](README.tr.md)

Analyzes the digital encoding chain for single-layer BD-R and screens input patterns for physical-disc light/dark mapping tests. The results do not define black/white polarity, generate a full-disc image, or perform burning. See the [analysis report](../../docs/BLURAY_BYTE_DENSITY.en.md) for detailed conclusions.

Requires the .NET 10 SDK. Independent standard-table analysis needs only the Python standard library; plotting additionally requires matplotlib / numpy. Run from the repository root:

The C# probe supports five languages for help, progress, errors, and explanatory JSON text. Choose explicitly with `--language zh-CN|zh-TW|en|ja|tr|system`; otherwise the `DISC_IMAGE_STUDIO_LANGUAGE` environment variable takes precedence, followed by the system UI language. JSON/CSV identifiers, numeric results, bit sequences, and filenames are not translated.

The Python reference searches and plotting tool also support the same `--language` option and environment preference. Help, errors, progress, chart annotations, generated Markdown, and explanatory JSON/CSV text are translated; field names, column names, pattern identifiers, and numerical data are preserved. Figures prefer available system fonts for the selected language and use the repository’s HarmonyOS font as a CJK fallback.

```powershell
dotnet run --project tools/BluRayByteProbe --configuration Release -- --language ja --help
dotnet run --project tools/BluRayByteProbe --configuration Release -- artifacts/bluray-byte-density 4
dotnet run --project tools/BluRayByteProbe --configuration Release -- --fine artifacts/bluray-byte-density

python tools/BluRayByteProbe/reference/analyze.py --output-dir artifacts/bluray-byte-density/reference
python tools/BluRayByteProbe/reference/pattern_search.py --output-dir artifacts/bluray-byte-density/reference
python tools/BluRayByteProbe/reference/robust_pattern_search.py --output-dir artifacts/bluray-byte-density/reference

dotnet run --project tools/BluRayByteProbe --configuration Release -- --verify-reference artifacts/bluray-byte-density/reference/independent-finite-vectors.json
dotnet run --project tools/BluRayByteProbe --configuration Release -- --verify-patterns artifacts/bluray-byte-density/reference/independent-pattern-vectors.json
python tools/BluRayByteProbe/plot_results.py artifacts/bluray-byte-density
```

The default command scans all 256 repeated Q bytes, including bare 17PP, four DC strategies for full clusters, four PSNs for candidates, a host control without scrambler cancellation, random neighbors, and mixed patterns. The second argument is parallelism (1–16). `--fine` scans all phases of five periods and four layouts, and rechecks results across addresses; parallelism in this mode is capped at 4.

Q means the **target user data after scrambling**. The actual host payload written is `Q XOR PSN mask`. All outputs go to the specified directory, and existing analysis files with the same names may be overwritten.

Main outputs:

| File | Contents |
|---|---|
| `all-bytes.csv` / `.json` / `.md` | All 256 bytes; density, DC sensitivity, and run distribution |
| `all-bytes-density.png` | 16 × 16 density map |
| `fine-patterns.json` / `.csv` | 176 bit-string/layout/phase combinations and address rechecks |
| `fine-pattern-comparison.png` | Comparison of byte baselines and bit-level control |
| `recommended-patterns.csv` | Full construction parameters and density for three recommended bit strings |
| `context.json` / `periodic-context.json` | Synthetic frames excluding ECC, neighbor tests, and DC boundary tests |
| `reference/` | Independent standard tables, exact cycles, and search results |
| `method.json` / `validation.json` / `fine-validation.json` | Measurement definitions and validation records |

The denominator for full-cluster statistics is fixed at `496 × 1932 = 958272` channel bits, including sync, EDC, LDC/BIS, DC, and 17PP. It excludes run-in/out/Guard3, but preserves the initial level and DSV from run-in. Automatic DC uses the project's existing greedy **diagnostic** algorithm, with future bits temporarily set to zero; it is not guaranteed to match the recorder's DC decisions. All-zero, all-one, and random DC are only sensitivity comparisons and must not be treated as actual burning configurations.

`FinePatternAnalysis` computes the physical ECC position of every controllable payload bit before filling in periodic bit values. It verifies that the 65,536 Q bytes after actual encoding match the target byte for byte. EDC, BIS, parity, and DC are all generated by the encoding chain; they are not assumed to be directly writable user bits.
