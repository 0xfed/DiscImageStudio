# CD / DVD 生成物理模型複核

[简体中文](PHYSICAL_MODEL_AUDIT.md) | [繁體中文](PHYSICAL_MODEL_AUDIT.zh-TW.md) | [English](PHYSICAL_MODEL_AUDIT.en.md) | [日本語](PHYSICAL_MODEL_AUDIT.ja.md) | [Türkçe](PHYSICAL_MODEL_AUDIT.tr.md)

複核日期：2026-09-21。對象為 `DiscImageStudio-GitHub` 目前工作區（包含尚未提交的標定實作），基準提交 `6c55a18`。本次僅進行標準核對、原始碼稽核與獨立數值驗證，未修改生成器、預設或燒錄行為。

## 結論

基礎螺旋公式與 DVD 磁區長度未發現計算錯誤。但是，目前模型無法僅憑標準名義參數精確預測實體光碟表面的角度：預設 CD 參數存在幾何一致性問題；固定線密度的單線標定會將密度誤差吸收到半徑；CD 交錯的有限串流邊界與參考時序也尚未納入幾何模型。此外，仍缺少燒錄媒體種類與生成模型的匹配檢查。

不能僅憑這次稽核確定某張實體光碟彎曲的唯一原因，也不應將 DVD 位元長度直接改為另一名義值作為修正。

## 標準依據與適用範圍

- 官方 [ECMA-359 第一版，2004](https://ecma-international.org/wp-content/uploads/ECMA-359_1st_edition_december_2004.pdf)：單層 DVD-R，主要檢查 §§10.7–10.9、18–23、24.2。核對了 PDF 第 28、29、52、56 頁原頁。
- 官方 [ECMA-267 第三版，2001](https://ecma-international.org/wp-content/uploads/ECMA-267_3rd_edition_april_2001.pdf)：DVD-ROM，主要檢查 §§10.6、18–21。不能用它取代全部可燒錄媒體的規則。
- 官方 [ECMA-130 第二版，1996](https://ecma-international.org/wp-content/uploads/ECMA-130_2nd_edition_june_1996.pdf)：CD-ROM 幾何與共用 CIRC 編碼參考，§§8.6、11.3–11.4、19.4、附錄 C。音軌並不等同於 CD-ROM 資料軌。
- 官方 [ECMA-394 第一版，2010](https://ecma-international.org/wp-content/uploads/ECMA-394_1st_edition_december_2010.pdf)：CD-R，多速錄製、預刻溝槽與 Red Book 相容關係，§§1.2、2.4–2.5。此文件透過引用 Red Book 規定部分幾何要求，並未直接重列完整的 CD 幾何表。

ECMA-359 的關鍵限制如下，均為標準要求，不可視為某一張光碟的實測值：

| 項目 | 限制 | 條款 |
|---|---|---|
| 資料起點半徑 | 23.9–24.0 mm | 10.7.1.2，原文為直徑 48.0 mm，公差 −0.2/+0.0 mm |
| 12 cm 光碟資料終點半徑 | 不超過 58.0 mm | 10.7.1.2 |
| 平均軌距 | 0.74 ± 0.01 μm | 10.8 |
| 局部軌距偏差 | 相對 0.74 μm 最大 ±0.03 μm | 10.8 |
| 平均通道位元長度 | 133.3 ± 1.4 nm | 10.9 |
| 資料區首 PSN | 0x030000，實體磁區連續無間隙 | 24.2 |

ECMA-267 的資料起點直徑下限與 DVD-R 不同：其 §10.6.1 為 48.0 mm，公差 −0.4/+0.0 mm。不能混用兩份標準的起點公差。

## 已確認正確的部分

DVD 的每磁區通道位元數為 `13 × 2 × (32 + 1456) = 38688`，每 16 磁區 ECC 區塊為 619008 位元。`DvdEccBlockEncoder.cs:8` 使用的數值正確；磁區偏移、同步框架與 PO 列交錯未發現通用長度漏算。

目前軌長為：

```text
CD:  L = (N / 75) × v                         [mm]
DVD: L = N × 38688 × channelBitLengthNm × 10^-6 [mm]
```

`CdDiscParameters.cs:59–75` 使用等軌距的面積近似，`ArchimedeanSpiral.cs:33–70,115–120` 使用精確弧長。其近似關係為 `pitch = π(ro²−ri²)/L`、`θ = 2L(r−ri)/(ro²−ri²)`。CD 近似與精確螺旋的整碟角差約 0.000135°，無法解釋肉眼明顯可見的彎曲。DVD 的精確弧長反解、奈米至毫米換算及預設影像座標方向也未發現錯誤。

DVD-R 的 linking 用於特定增量附加情況；§24.2 明定磁區連續。沒有依據為每個 ECC 區塊統一附加一段所謂隱藏間隙。

## 發現一：預設 CD 80 分鐘參數組合不合理

`src/DiscImageStudio.Core/Presets/built-in-disc-presets.json:6–12` 同時使用 359849 磁區、24.5–56.8 mm、1200 mm/s。依實際生成公式反算：

| 預設 | 隱含軌距（μm） |
|---|---:|
| CD 80 分鐘預設 | 1.432856 |
| CD 74 分鐘預設 | 1.548384 |
| 錸德水藍 CD 實測半徑預設 | 1.492598 |
| Verbatim CD 實測半徑預設 | 1.500257 |
| DVD 12 cm 預設 | 0.739837 |
| Verbatim DVD-R 實測半徑預設 | 0.738304 |

ECMA-130 §11.3 的軌距範圍為 1.5–1.7 μm；§11.4 的基準掃描速度範圍為 1200–1400 mm/s。CD80 預設組合顯然不能作為符合該幾何範圍的通用精確預設。其 24.5 mm 起點也不能直接等同於 §8.6 的使用者資料區起點（24.8–25.0 mm）。

這是對軟體參數組合的檢查，並非據此判定使用者的 CD-R 光碟不合格。標示為實測的預設仍固定採用 1200 mm/s，不代表線密度也經過測量。不能僅為落入標準範圍而擅改使用者實測半徑。

## 發現二：標準公差遠大於繪圖所需的累積角度精度

`ImageTargetMapper.cs:58–77`、`FastDispersionImageWriter.cs:345–365` 使用容量、兩個半徑及固定位元長度反求恆定軌距。DVD 預設參數產生約 45956.06 圈。標準允許局部軌距變化，且 58 mm 為上限，因此這些輸入只能構成初始模型。

數值敏感度（均為改變一個輸入、其餘保持不變的模型對照）：

- DVD 位元長度改變 10 ppm，整碟累積角度改變約 165.44°。
- DVD 位元長度由 133.33 改為 133.3 nm，累積角度改變約 10.34037 圈。
- DVD 內半徑或外半徑增加 0.001 mm，累積角度改變約 −201.76°。

上述數值為模型相位差，不是已測得的實體光碟誤差。133.33 nm 在標準公差內；133.3 nm 也不是每張光碟的真實精確位元長度。盲目替換名義值可能顯著改變生成結果。

## 發現三：單條徑向線無法獨立確認半徑與線密度

`CalibrationTarget.cs:468–473` 固定線速度／位元長度，`CalibrationCrossFitter.cs:73` 僅擬合兩個半徑及整體旋轉；目前流程不使用同心圓的來源半徑對應關係。

獨立反例：生成模型為 DVD `(ri=24, ro=58, bit=133.33)`，假設真實模型為 `(24,58,133.3)`。固定擬合位元長度仍為 133.33，僅將候選半徑改為約 `(24.00540257,58.01305620)`，再調整整體旋轉，即可在 25–57 mm 範圍幾乎完全重現同一條彎曲線（2049 點精確弧長計算的最大相位殘差約 2.04×10^-10 rad）。候選在預設 ±0.02 mm 搜尋範圍內。這是解析建構候選後的前向驗證，並未聲稱目前最佳化器必然回傳這組候選。

因此，低殘差可能只是將位元長度誤差解釋為半徑誤差。現有功能可以取得實用的補償參數，但結果應理解為「固定線密度假設下的等效參數」。若要確認真實物理半徑與密度，需要加入已知來源半徑的圓環、已知資料位置或獨立邊界測量；單純多開放一個擬合參數仍無法解決資訊不足。

## 發現四：CD 交錯補償有有限串流邊界效應，物理時序原點待驗證

`CddaInterleaver.cs:8–16` 的延遲表與 ECMA-130 圖 C.4 的資料路徑一致，並非錯誤的重複交錯。獨立標籤模擬將現有補償後 PCM 再送入標準正向 CIRC 的 24 個資料路徑：10 磁區測試中 20856 個穩態資料位置全部一致，但組合結果為目標圖案整體延後 111 框架。

需嚴格區分兩件事：

- **確定的有限串流現象：**初始化產生 1332 個零值佔位位元組；末端分散於最後 108 框架的 1332 個目標位元組未輸出。`CddaInterleaver.cs:46–55` 的 Flush 僅處理磁區尾部，整磁區輸入時不會排空環形緩衝區。這會影響圖案邊界。
- **有條件的物理偏移：**111 框架為圖 C.4 參考時序下的組合延遲，約 15.102 ms，在 1200 mm/s 下約為 18.122 mm 弧長。若未被燒錄鏈路的時序原點抵銷，角差會隨半徑改變，無法僅以起始角消除。尚未測量其相對 ATIP、INDEX 01 及實體光碟資料起點的關係，因此不能直接宣稱為已證實的實體光碟偏移。

`CdTrackGenerator.cs:229–246` 按未加入上述時序的 globalByte 取樣，幾何標定同樣不包括這一級編碼。現有相容說明也已聲明預覽不模擬完整 CIRC/EFM。需補充端到端物理時序驗證，不能僅憑同源生成與預覽一致就證明盤面位置正確。

## 發現五：燒錄媒體類型未與模型匹配

`WindowsImapiBurner.cs:151–166,377–390` 僅檢查 IMAPI 支援、空白狀態與容量，未查詢實際物理媒體種類。生成器卻採用單層 ID（`DvdDataFrameBuilder.cs:41`）及單層單向螺旋。

這缺少對雙層 DVD、DVD-RAM 等不同物理格式的主動攔截。IMAPI 能寫入某種媒體，不代表目前繪圖模型適用；實際是否能開始寫入仍取決於裝置與狀態。雙層的換層、第二層方向及位元長度尚未建模。

可使用微軟的 [CurrentPhysicalMediaType](https://learn.microsoft.com/en-us/windows/win32/api/imapi2/nf-imapi2-idiscformat2data-get_currentphysicalmediatype) 與 [物理媒體列舉](https://learn.microsoft.com/en-us/windows/win32/api/imapi2/ne-imapi2-imapi_media_physical_type) 進行匹配檢查。

## 建議的修正順序

1. 為預設增加隱含軌距檢查，區分標準初值、實測值與補償所得值；優先處理 CD80 預設組合。明確說明起訖半徑對應哪個資料位置，並將繪圖裁切範圍與軌道錨點分開。
2. 核實 CD 交錯、音軌起點及燒錄鏈路的聯合時序；再修正取樣偏移與頭尾策略，保持最終磁區數不變。
3. 為標定增加獨立的徑向或資料位置限制。若實測殘差仍有系統性局部彎曲，再評估變軌距／相位修正模型。
4. 寫入前檢查實際媒體類型與容量是否符合所選模型。

本次未進行實體光碟燒錄或光學亮度測量。驗證包括標準原文與原頁、公式重算、精確螺旋數值對照、參數不可辨識反例及 CIRC 資料路徑標籤模擬；未將這些檢查延伸宣稱為完整光學模擬或實體光碟精度認證。
