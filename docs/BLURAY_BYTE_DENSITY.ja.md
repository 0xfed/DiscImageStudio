# 単層 BD-R：バイトとビット周期の遷移密度分析

[简体中文](BLURAY_BYTE_DENSITY.md) | [繁體中文](BLURAY_BYTE_DENSITY.zh-TW.md) | [English](BLURAY_BYTE_DENSITY.en.md) | [日本語](BLURAY_BYTE_DENSITY.ja.md) | [Türkçe](BLURAY_BYTE_DENSITY.tr.md)

2026-10-24。提供された ISO/IEC 30190:2021、特に 13.15–13.18 と Figure 40/41 に基づき、本プロジェクトの EDC、スクランブル、LDC/BIS、DC、17PP エンコード処理で数値実験を行いました。単層ディスクだけを対象にしています。

**総遷移密度を目的にする場合、ビット単位で構成したパターンを採用する価値があります。** 最良の繰り返しバイト基準は完全クラスターで約 **19.20% / 38.61%** ですが、物理インターリーブと DC 区間境界を考慮したビット周期方式では **15.95% / 43.37%** に達しました。両端の密度差は 19.41 から 27.42 パーセントポイントへ、約 41% 増加します。これはデジタル符号化の結果であり、実ディスクの反射輝度と白黒方向は未確定です。現在の描画はユーザーの選択に従って以下の **3T / 6T 回数の偏り**を利用し、この密度極値方式は使いません。

## 3T / 6T 回数マッピングの描画への組み込み

同じ 958,272 チャネルビットの完全クラスターで、隣接する modulation ONE 間の完全な間隔が 3T または 6T となる**絶対回数**を数えます。マークとスペースを両方数えます。NRZI レベルのデューティ比でも、対象ラン数 / 全ラン数による順位でもありません。

| 既定の画像端 | スクランブル領域 Q | 基準クラスターの対象ラン数 | 対象ラン比率 | 四つのアドレスでの対象回数範囲 |
| --- | --- | ---: | ---: | ---: |
| 暗部（0–127）、3T 寄り | `AA` | 265,136 | 85.4164% | 264,946–265,186 |
| 明部（128–255）、6T 寄り | `44` | 116,575 | 62.6862% | 116,470–116,659 |

両者は基準 PSN `0x100000` の 256 種すべての繰り返しバイトで、それぞれ対象回数が最大です。6T 比率が最大の `22` は 62.7744% ですが、6T は 116,402 回で `44` より少ないため、回数モードでは `44` を選びます。`0x100000`、`0x234560`、`0x6D3A00`、`0xCA73E0` の 4 アドレスで再確認すると、`44` の 6T 平均回数は 116,559.5 で、`11` の 116,526.5 と `22` の 116,457 をわずかに上回ります。すべてのアドレスで最適という意味ではありません。

実運用の `BluRayRunLengthMapping` はしきい値 128 で `AA` / `44` を選び、白黒方向を反転できます。`BluRayImagePayloadMapping` が画像位置をサンプリングし、ストリーミング生成器がスクランブルを打ち消してホストペイロードを出力します。画像境界、EDC、ECC、BIS、DC、同期は他のラン長を生むため、「3T / 6T に偏る」は純粋な 3T / 6T を意味しません。既定の明暗割り当ては反転可能な画像規約であり、実ディスクの反射輝度を校正したものではありません。

これらの値は現在の貪欲 DC 診断モデルによります。生の回数は `all-bytes.json` の `Cluster.RunCounts` にあります。アーキテクチャ回帰テストは完全 RUB エンコードでディスク先頭・末尾の回数偏向を検証し、混合画像のスクランブルと ECC 位置も確認します。コマンドと使い方は [Blu-ray ガイド](ADDING_BLURAY.ja.md)を参照してください。

## 測定の定義

- 遷移密度 = modulation ONE 数 / チャネルビット数。ONE は 1 回の NRZI 反転を表し、NRZI レベル内の ONE 比率では代用できません。
- Q は**スクランブル後の目標ペイロード**です。ホストペイロードに `Q XOR scramblingMask` を書きます。生のホストバイトをそのまま繰り返すと目標パターンを失います。
- 純粋な 17PP 結果には DC、ECC、BIS、同期を含めず、独立した規格表と有限状態の正確な周期計算を用います。
- 完全クラスターは 65,536 ホストバイトから生成し、EDC、LDC parity、BIS、DC、同期を含む `496 × 1932 = 958272` チャネルビットを数えます。run-in/out/Guard3 は除きますが、run-in 終了時のレベルと DSV を使います。
- 既定 PSN は `0x100000`、アドレス flags と user control data はゼロです。候補は `0x234560`、`0x6D3A00`、`0xCA73E0` でも検証します。
- 主結果は、将来の制御ビットを一時的にゼロとする現在の貪欲 DC 診断アルゴリズムによります。書き込み装置と同じ判断は保証しません。全 0、全 1、固定シードのランダム DC は追加の感度実験であり、実際の記録手順を指定するものではありません。

## 全 256 バイトの基準

単一の Q バイトを連続して繰り返すと、DC/ECC なしの定常状態では密度は 4 段階だけになります。

| 純粋な 17PP 密度 | バイト数 |
| --- | ---: |
| 1/6 = 16.6667% | 28 |
| 1/4 = 25% | 92 |
| 1/3 = 33.3333% | 100 |
| 5/12 = 41.6667% | 36 |

このうち **80 バイトは奇数ビットずらすと密度の段階が変わります**。DC 挿入で 2 ビット解析の位相が変わるため、この裸の符号表だけでは順位を付けられません。

| Q | 純粋な 17PP | 完全クラスター・貪欲 | 四つの PSN の完全クラスター範囲 | 試験用途 |
| --- | ---: | ---: | ---: | --- |
| `09` | 16.6667% | 19.1997% | 19.1962–19.2080% | 走査中で最低の繰り返しバイト |
| `11` | 16.6667% | 19.4820% | 19.4447–19.4820% | 純粋な符号化はすべて 6T、長いランの対照 |
| `22` | 16.6667% | 19.3505% | 19.3242–19.3510% | 同じ頑健な低密度群 |
| `3D` | 41.6667% | 38.4602% | 38.4428–38.4739% | 頑健な高密度バイト |
| `7A` | 41.6667% | 38.5486% | 38.5409–38.5525% | 頑健な高密度バイト |
| `9E` | 41.6667% | 38.6143% | 38.6014–38.6260% | 走査中で最高の繰り返しバイト |
| `00` | 33.3333% | 32.8615% | 32.8412–32.8668% | 一般入力の対照 |
| `FF` | 33.3333% | 32.5332% | 32.5332–32.5639% | `00` と大きな密度差はない |

`55/AA` の完全クラスター密度も約 32.30% / 32.39% で、密度両端には適しません。スクランブルを打ち消さないと、試した定数ホスト 14 候補はすべて約 29.37–29.67% に入り、元の差はほぼ消えます。

## より細かい単位で達成できるパターン

17PP は 2/4/6/8 入力ビットの可変長規則で符号化し、前の変調ビットと特別置換規則も持ちます。バイトは格納単位であり、独立した符号語として扱えません。

| 生の周期ビット列 | 周期長 | バイト格納例 | 純粋な 17PP 密度 | 定常ラン |
| --- | ---: | --- | ---: | --- |
| `0001` | 4 | `11` | 16.6667% | すべて 6T |
| `00111101` | 8 | `3D` | 41.6667% | 3 個の 2T、2 個の 3T |
| `001111` | 6 | `3C F3 CF` | 44.4444% | 3 個の 2T、1 個の 3T |
| `0000101101110010` | 16 | `0B 72` | **12.5%** | すべて 8T |
| `0111011110` | 10 | `77 9D E7 79 DE` | **46.6667%** | 6 個の 2T、1 個の 3T |

通常の 17PP データ区間のランは 2T–8T で、2T の連続は最大 6 個です。そのため長いデータ区間の密度下限は `1/8`、上限は `7/(6×2+3)=7/15` で、上記の 16 ビットと 10 ビットのパターンがそれぞれ到達します。同期には 9T があるため、同期を含む任意の短い窓にこの限界を直接適用できません。

両極値の周期は奇数ビット位相では 29.1667% / 33.3333% に劣化します。6 ビットの `001111` は両位相とも 44.4444% ですが、裸の NRZI デューティ比は 4/9 またはその補数で、DC 制御による平衡が必要です。16 ビット以下の周期探索では、偶数・奇数の両位相に頑健な最高密度パターンです。

パッキング例は周期の表現方法を示すだけです。**これらのホストバイトをそのまま繰り返したり、元のペイロード順で Q を繰り返してインターリーブを無視したりしてはいけません。** 例えば 6 ビット周期をペイロード順に Q に埋めると、完全クラスターは約 33.43–34.39% にとどまり、物理 ECC 順に並べて初めて約 40.64–40.75% になります。

## DC 補償と完全クラスターの結果

各フレームは 155 ECC バイト、計 1240 生ビットです。最初に 25 データビットがあり、以後 45 データビットごとに DC ビットを挿入し、合計 28 個です。bit 0 を MSB として `j=8×EccColumn+bitWithinByte` とします。

```text
DCbefore(j) = j < 25 ? 0 : 1 + floor((j - 25) / 45)
```

DC スロットを予約：

```text
index = RecordingFrame × 1268 + j + DCbefore(j)
Qbit = pattern[(index + phase) % period]
```

DC データ区間ごとに再開：

```text
index = j < 25 ? j : (j - 25) % 45
Qbit = pattern[(index + phase) % period]
```

DC 挿入後は各区間が偶数入力ビットから始まるため、周期を再開すると 2 ビット解析の位相を保てます。スロット予約方式は位置だけを確保し、DC ビット値はエンコーダー／書き込み装置が選びます。EDC、BIS、parity も任意に制御せず、通常どおり生成します。

これらの物理位置で Q を構成した後、対応するペイロードバイトへ逆に散布し、スクランブルを打ち消します。既存の `Map(luminance, position)` は RecordingFrame/EccColumn を提供します。1 回の呼び出しで 8 ビットを個別に生成すればよく、返す値を固定バイトに制限する必要はありません。

| 推奨ビットパターン | 構成 | 位相 | 完全クラスター・貪欲 | 四つの PSN での範囲 | 他の三つの DC 戦略の範囲 |
| --- | --- | ---: | ---: | ---: | ---: |
| 16 ビット `0000101101110010` | DC 区間で再開 | 2 | **15.9500%** | 15.9405–15.9500% | 15.9278–17.0720% |
| 6 ビット `001111` | DC スロット予約 | 3 | **40.8172%** | 40.8158–40.8315% | 41.0010–41.4603% |
| 10 ビット `0111011110` | DC 区間で再開 | 4 | **43.3670%** | 43.3662–43.3713% | 42.1870–43.3904% |

位相は 0 起点で、上式の座標に加える周期オフセットです。各クラスターの座標は原点から再開します。これらの位相はこの構成方法だけに対応し、物理信号全体を同じビット数だけ任意にずらすことではありません。

6 ビット方式の全位相での完全クラスター密度は 40.7929–40.8172% で、位相変化の影響は小さいです。極値の 16/10 ビット方式は選んだ位相の維持が必要で、誤った位相では約 30%–32% に戻ることがあります。DC 感度区間は測定した数戦略だけの範囲であり、任意の書き込み装置で保証する範囲ではありません。

推奨低密度パターンでは、完全な遷移間ランの **52.65% が 8T**、推奨高密度パターンでは **79.14% が 2T** です。平均密度だけより具体的な実ディスク比較ができます。貪欲モデルでは両者の NRZI レベル占有率は約 50% のため、ビット値 0/1 を視覚的な白黒と直接解釈できません。

## 最初の実ディスク試験候補

同じディスク、書き込み速度、観察条件で以下の単色パッチを比較し、内周・中間・外周に繰り返し配置することを勧めます。

1. 低密度端：16 ビット周期、DC 区間ごとに再開、位相 2。
2. 高密度端：10 ビット周期、DC 区間ごとに再開、位相 4。
3. 頑健な高密度対照：6 ビット周期、DC スロット予約、位相 3。
4. バイト基準：`09`、`11`、`9E`。`00` は通常入力の対照にもできます。

まず大きなパッチで実際の明暗と観察角度を回したときの安定性を比較し、その後で領域混合と画像マッピングを試します。2 パターンをバイトごとに交互にすると符号化の文脈が変わるため、密度や輝度を両端の線形平均と仮定してはいけません。これらの密度極値候補はまだ実ディスクへ書き込んでおらず、現在の既定の白黒マッピングにも使っていません。

## 検証と再現

- 独立した Python 実装は規格の Figure 41 を転記し、C# の 256 個の 4 バイトベクトルと 298 個の周期ベクトルにビット単位で一致します。
- 長さ 2–16 の全 131,068 生ビット列を、それぞれ 2 種の先行ビットで全探索し、計 262,136 回の正確な周期計算を実行しました。14,694 個の 2 ビット回転同値類を検証しました。上記の位相頑健な最適性はこの探索範囲に限定されます。
- 完全処理で 256 バイトすべてを走査しました。合成フレームでは各バイトについて、8 種 DC mask × 31 種同期位置 × 2 種の前フレーム termination も確認しました。
- 細粒度パターンは計 176 パターン／配置／位相組み合わせと、追加の 120 アドレス再確認クラスターです。各クラスターで 65,536 個の制御可能 Q バイトが実 ECC 位置で目標と一致することを検証します。
- クラスター長、ラン数保存、RLL 間隔のチェックに合格し、高速クラスター走査は完全 RUB 経路と一致します。純粋なデータには 2T–8T 以外の完全なランはなく、同期を含むクラスターでは 9T を許可します。

ツールとコマンドは [BluRayByteProbe](../tools/BluRayByteProbe/README.ja.md) を参照してください。生の結果は `artifacts/bluray-byte-density/` にあり、artifacts ディレクトリはリポジトリ規則で無視されます。スクリプトで再生成できます。実運用では本ページで別に示した 3T / 6T 回数マッピングを採用済みです。
