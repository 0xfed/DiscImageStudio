# Blu-ray モード（単層 BD-R）

[简体中文](ADDING_BLURAY.md) | [繁體中文](ADDING_BLURAY.zh-TW.md) | [English](ADDING_BLURAY.en.md) | [日本語](ADDING_BLURAY.ja.md) | [Türkçe](ADDING_BLURAY.tr.md)

Blu-ray の実装は `src/DiscImageStudio.BluRay` にあり、メディアに依存しない Core と `src/DiscImageStudio.Iso` を参照し、CD/DVD エンコーダーには依存しません。ISO/IEC 30190:2021 に基づき、現在の対象は **120 mm、単層 25 GB BD-R** です。2 層、BDXL、BD-RE、Blu-ray ビデオのオーサリングには対応していません。

## アプリ内での位置付け

Blu-ray は 6 番目のワークスペースではなく、プロジェクトの 3 番目のディスク種類（CD / DVD / BD）です。BD プロジェクトを開くと、次のように動作します。

- **デザイン**：キャンバスと合成画像を BD の生成外半径に合わせて配置します。左パネルの「ディスク内ファイル」でフォルダーと内周／外周の配置を選択し、エクスポートページと同期します。右パネルの階調モジュールは 2 階調、sRGB 線形化、明るさ、3T/6T 極性に対応します。
- **プレビュー**：デザイン投影は生成／実測ジオメトリ、階調、極性から 3T/6T 分類図を描画します。生成物の読み戻しは極性を適用せず、ISO の AA/44 ペイロードバイトを直接分類します。表示するのは反射輝度ではなく分類図です。
- **エクスポート**：完全な BD ISO（描画専用または UDF 2.01 ファイル付き）を生成します。フォルダー選択後、ファイルを内周または外周に配置でき、既定は内周です。配置はプロジェクトに保存し、同じディレクトリの `<iso>.json` サイドカーにも記録します。
- **書き込み**：同じ ISO ストリームを MMC の逐次書き込みへ直接送り、完全なイメージは保存しません。ジョブドックで進捗とキャンセルを扱います。
- **校正**：BD ターゲットはデータ領域全体を覆い、セクター、半径、極性、描画範囲の開始・終了、ISO タイムスタンプを保存します。フィッティングは一定トラックピッチを使用し、結果を BD パラメーターに反映します。

BD プリセットは CD/DVD とともに `disc-presets.json`（schema 4）の `bluRayPresets` に保存します。組み込みは「標準 25GB 単層 BD」「Ritek BD-R 10x」「Ritek BD-R 12x」「Verbatim BD-R (64099)」「Verbatim BD-R (64293)」です。ユーザープリセットはプロジェクト設定ダイアログの下部から保存できます。

## 容量とジオメトリ

- 単層容量は 2048-byte ユーザーセクター 12,219,392 個、すなわち 25,025,314,816 bytes です。32 セクターで 65,536-byte クラスターを構成します。
- プロジェクトの区画のセクター数は単層容量以下の 32 の正の倍数で、外半径は 60 mm 以下である必要があります。
- 生成と書き込みで総セクター数を共有します。書き込みでは常にディスク全容量を宣言し、ファイルとメタデータ以外の未使用セクターはゼロのペイロードです。
- 公称トラックピッチは 0.320 µm、チャネルビット長は 74.5 nm、開始角は 0° です。

## 生成と ISO

`BluRayIsoGenerator` は UDF 2.01 のディレクトリとファイル extent を計画してから、32 セクター境界に揃えた描画範囲を割り当てます。内周モードではファイル区画を前方に、外周モードではディスク末尾の予約領域の直前に配置します。先頭の識別情報、アンカー、末尾のバックアップ情報は規定の位置に残します。出力長は `TotalSectors × 2048` に固定されます。

- フォルダー未選択：データ領域全体を描画専用とし、ファイルシステムを含めません。この `.iso` は本アプリで読み戻せますが、一般のファイルシステムツールでは参照できません。
- フォルダー選択済み：UDF 2.01 を書き込み、4 GiB を超える単一ファイルに対応します。`--file-position inner|outer` で配置を選び、既定は `inner` です。`outer` には `--data-dir` が必要です。ファイル、パディング、パターン、末尾メタデータを単一の前進ストリームで書き出します。
- 出力先は入力フォルダーの外で、入力画像を上書きしないパスにする必要があります。キャンセルや失敗時には既存の ISO を保持します。
- 生成に成功すると `<iso>.json`（`format: bd-r-image-v1`）に、総セクター数、内外半径、描画範囲とその半径、3T/6T 極性、`ToneProfile`、ボリュームラベル、UDF タイムスタンプ、入力画像、生成時刻を書き出します。プレビューでこの ISO を選ぶと自動復元します。サイドカーのない外部 ISO も、現在のプロジェクトのジオメトリで読み戻せます。

ファイルは通常のユーザーバイトを使い、パターン用の逆スクランブルを適用してはいけません。パターンは元のディスク全体のセクターアドレスとジオメトリを維持し、残った描画領域をディスク全体に引き伸ばしません。UDF 区画はファイルシステムの領域だけを覆い、パターンをファイルシステムの空き領域として示しません。実際の描画可能範囲はファイル占有量と末尾バックアップ領域で決まります。GUI のデザイン投影とサイドカー付き生成物の読み戻しでは、ファイルシステムを含むファイル領域を黄色と凡例で示します。配置情報のない外部 ISO ではファイル範囲を推測しません。

`BluRayIsoGenerator.Prepare` は最初にフォルダーを走査し、UDF 2.01 のディレクトリとファイル extent を計画します。内周配置ではファイル末尾を 32 セクター境界へ切り上げ、外周配置ではファイル区画の先頭を 32 セクター境界へ切り下げます。末尾の 288 セクターをバックアップボリューム記述子とアンカー用に予約します。このファイルシステム API はフォルダー未指定でも空ボリュームを保持します。完全な描画クラスターが少なくとも 1 個必要で、最小テスト容量は 640 セクターです。

ファイル出力とストリーミングは前進書き込み経路を共有します。計画後に入力ファイルやディレクトリの内容が変わると、古い配置の再利用を拒否します。ファイル長は 64 ビットフィールドで扱い、大きなファイルをそれぞれ `0x3ffff800` バイト以下の割り当て extent に分割し、128 KiB バッファーで逐次読み込みます。単一ファイルの上限は 4 GiB ではなくディスク残容量です。DVD の ISO9660/Joliet 経路は変更しません。

UDF 実装は [ECMA-167](https://ecma-international.org/publications-and-standards/standards/ecma-167/) と [ECMA TR/112-4（UDF 2.01）](https://ecma-international.org/wp-content/uploads/ECMA_TR-112-4_1st_edition_december_2023.pdf) に基づき、クローズ済みの読み取り専用ボリュームを書き込みます。データディスク用であり、Blu-ray ビデオのオーサリングは提供しません。

## 階調と極性

BD の階調処理は入力画像の解像度で一度だけ実行します。sRGB 線形化 → 明るさオフセット → バイト単位のディザリング → しきい値 128 での二値化、という順序です。生成、書き込み、プレビューは同じ二値ラスターを共有し、約 250 億個のペイロードバイトを個別にハッシュ処理しません。

`BluRayRunLengthMapping` は最終段だけを担当します。暗部には 3T 回数に偏る `AA`、明部には 6T 回数に偏る `44` を書き、`InvertMapping` で両端を交換します。これは画像マッピングの規約であり、純粋な 3T/6T や実測の光学極性を保証しません。実際の明暗方向は校正ディスクで観察する必要があります。極性は `ToneProfile` とは別に保存します。

## 3T / 6T 回数マッピングと拡張

画像経路は `BluRayImageLoader` でデコードして透明部分を白地に合成し、`BluRayImagePayloadMapping` でサンプリングします。縦横比を維持し、最長辺がディスク外径に対応し、空白は白になります。サンプル位置には各フレームの EDC 予約位置、LDC インターリーブ、BIS 挿入、DC ビット、同期、run-in を含めます。2:3 の変調率で計算するのは公称バイト中心であり、可変長 17PP 符号語の正確な境界ではありません。

組み込みの `BluRayRunLengthMapping` は 128 を境に、スクランブル領域の `AA` または `44` を返します。選択の基準は、同じ 958,272 チャネルビットの完全なクラスターで、隣接する modulation ONE の間隔が 3T / 6T となる回数です。マークとスペースの両方を数え、特定レベルのデューティ比ではありません。基準 PSN `0x100000` での 256 種の繰り返しバイト走査では、`AA` は 3T が 265,136 回、`44` は 6T が 116,575 回で、それぞれ対象回数が最大です。4 アドレスでの再確認でも強い偏りを維持しますが、すべてのアドレスで首位とは限りません。詳細は[バイト分析](BLURAY_BYTE_DENSITY.ja.md#按-3t--6t-数量接入绘图)を参照してください。

`IBluRayLuminanceMapping.Map` を実装すると、入力輝度と公称バイト位置に応じたスクランブル領域のバイトを返す別の戦略に置き換えられます。画像以外の実験では `IBluRayPayloadMapping.FillScrambledPayload` を直接実装して、セクターの 2048 ユーザーバイト位置を埋め、`BluRayStreamingGenerator` に渡せます。コールバックは公称セクター、PSN、ディスクパラメーターを受け取ります。

`BluRayDiscModule` はコンストラクターで画像デコードデリゲートを受け取り、WPF 非依存を保ちます。App の CLI は `BluRayImageLoader.Load` を使用します。モジュール API で画像を生成する場合もこのデリゲートを渡してください。`BluRayConstantByteMapping` は明示的なデジタル実験専用です。画像と校正のどちらも `BluRayIsoGenerator` でファイルを生成するか、書き込み装置にストリームを供給します。

候補選別は[バイトとビット周期の密度分析](BLURAY_BYTE_DENSITY.ja.md)を参照してください。`tools/BluRayByteProbe` で 256 バイトすべてと細粒度の周期について、完全なクラスターの統計を再現できます。周期ビット列は別の実験戦略で、現在の回数マッピングは繰り返しバイトを使用します。分析結果では実ディスクの白黒極性をまだ指定していません。

## コマンドライン

```powershell
# 単層ディスクのパラメーターを確認、または JSON を出力
dotnet run --project src/DiscImageStudio.App -- bd-info --output bd-parameters.json

# 描画専用 ISO（1024 セクターは簡易機能確認用で、実際の全ディスク構成ではない）
dotnet run --project src/DiscImageStudio.App -- bd-generate --input image.png --output bd-test.iso --total-sectors 1024 --invert true

# UDF 内周ファイル付きの全容量 ISO
dotnet run --project src/DiscImageStudio.App -- bd-generate --input image.png --output bd-image.iso --data-dir C:\Files --volume-label BD_IMAGE

# 階調：ディザリング、明るさ、sRGB 線形化
dotnet run --project src/DiscImageStudio.App -- bd-generate --input image.png --output bd-tone.iso --tone-dither 0.75 --tone-gamma true --tone-brightness -4

# 生ペイロードのプローブと単一 ECC クラスターの診断
dotnet run --project src/DiscImageStudio.App -- bd-probe --byte 0xA6 --sectors 32 --output bd-probe.bin
dotnet run --project src/DiscImageStudio.App -- bd-encode --input bd-probe.bin --psn 0x100000 --output bd-ecc.bin
```

`bd-generate` の `--preset` は `bd-r-sl-25gb`、`bd-r-ritek-10x`、`bd-r-ritek-12x`、`bd-r-verbatim-64099`、`bd-r-verbatim-64293` を選べます。`--total-sectors`、`--r0`、`--r1`、`--start-angle` で対応する値を上書きできます。`--invert` は `true`/`false` を受け取ります。`bd-generate` は旧 `--start-sector` / `--sectors` の部分範囲パラメーターを受け付けず、部分範囲は `bd-probe` でのみ使用できます。

`bd-probe` の `--byte` は 0..255 または `0x00`..`0xFF` で、範囲は 32 に揃えます。`bd-encode` の入力は正確に 65,536 bytes で、出力は 76,880 bytes の ECC クラスターです。17PP、DC-control、ファイルシステムを含まず、書き込み可能なイメージとしては使えません。

## エンコード処理

| 構成要素 | ISO/IEC 30190:2021 |
| --- | --- |
| 2048-byte ペイロード + 4-byte EDC | §13.2–13.3 |
| 16-bit LFSR、PSN bits 19..5 からシードを導出、data frame ごとにリセット | §13.4 |
| LDC RS(248,216)、304 符号語とインターリーブ | §13.5–13.8 |
| アドレス、RS(9,5)、BIS RS(62,30)、多重化 | §13.9–13.14 |
| 17PP、DC-control、同期フレーム | §13.15–13.17 |
| 記録単位間隔 | §14 |
| 公称トラックピッチ 0.320 µm | §15.4.3 |
| 単層 PSN 0x00100000..0x00CA73FF | §17 |
| 単層データ領域 381,856 クラスター | §19 |

パターンテストで書き込むのは**逆スクランブル済みのユーザーペイロード**です。実際のドライブは EDC を計算した後、2052-byte data frame 全体をスクランブルします。EDC、誤り訂正、アドレス、同期などのデータを、指定バイトのプローブで任意に上書きすることはできません。

`BluRayRecordingFrameEncoder` は呼び出し側が明示的に渡す 28 個の DC 制御ビットを受け取ります。`BluRayRecordingUnitEncoder` はさらに run-in、496 フレーム、run-out、任意の Guard3 を含む診断シミュレーションを提供し、各変調ビット／NRZI レベルを 1 バイトで表します。自動戦略は明確に `BluRayGreedyDcControlEncoder` と名付けており、未確定の後続ビットを 0 として先読み貪欲選択を行います。後続制御ビットの確定で以前の局所最適解が変わることがあり、返される `SuboptimalDcControlDecisions` がこれを報告します。この戦略は実験用で、規格が要求する最終 DC 最適性や、書き込み装置の実際のビット列との一致を保証しません。CLI の `bd-encode` は確定的な ECC 段階だけを出力し、この診断シミュレーションを記録可能イメージとして出力しません。

`BluRayTrackGeometry` は独立した一定ピッチ螺旋を使用し、手動設定の総セクター数に対応する総トラック長と内外半径から有効ピッチを求めます。最後のセクターは設定した外半径に到達します。データ面から見ると、固定ディスク座標のサンプリング軌跡は時計回りに外へ進みます（§9.8、§15.3）。画面変換では Y 軸を 1 回だけ反転します。各記録単位の幅は `2760 + 496 × 1932 + 1104 = 962136` チャネルビットで、ビット長は 74.5 nm です。`bd-probe` の局所範囲も全容量のジオメトリを使用します。列末尾の Guard3 は各記録単位の繰り返し幅に含めません。

既定の 24–58 mm は公称ジオメトリであり、特定ディスクの実測値ではありません。組み込みストリーミング書き込みは、BD-R を未フォーマットのまま欠陥管理用予備領域を割り当てずに保ち、`sector → PSN` モデルに合わせます。実際の半径、位置、光学コントラストは実ディスクでの校正が必要です。外部ソフトウェアで ISO を書き込む場合も予備領域なしの方式を使ってください。

## 予備領域なしのストリーミング書き込み

`IDiscFormat2Data` が未フォーマット BD-R に報告する使用可能容量は、既定の予備領域構成では 11,826,176 セクターとなる場合があり、生の 12,219,392 セクターより 768 MiB 少なくなります。Blu-ray 経路は `IDiscRecorder2Ex.SendCommandSendDataToDevice` で LBA 0 から `WRITE(10)` を順に送信し、1 回あたり 32 セクター（64 KiB）、コマンドのタイムアウトを 200 秒として初回書き込みの初期化時間を確保します。バッファーはアダプターのアドレス整列と最大転送量の制約に従います。この経路ではデータ書き込みインターフェースの `Write`、`FORMAT UNIT`、予備領域割り当て操作を呼びません。

公開の `IWriteEngine2` インターフェースには設定可能なコマンドタイムアウトのプロパティがないため、照会やキャッシュフラッシュのタイムアウトを設定しても `WriteSection` 内の待機は延長できません。現在の明示的コマンド経路は、失敗コマンドの LBA、セクター数、実際の経過時間、HRESULT、Sense を報告します。タイムアウトでは装置側の結果が不確定な場合があり、その範囲を自動再送しません。

失敗ログには直近 8 回の成功書き込みの時系列も残し、入力ストリームの読み取り待機、装置コマンド待機、累積の受領確認データ量を分けて集計します。有効な Sense がない場合は「有効な装置 Sense データが返されませんでした」と明示し、全ゼロの戻り値をディスクにエラーがないという意味に解釈しません。`0x8007048F` は Windows が装置の切断を報告したことを示します。200 秒のタイムアウトを設定したコマンドが数ミリ秒で失敗し、その後装置が再列挙されるなら、待機不足だけでなく接続、ファームウェア、USB イベントを調べる必要があります。このインスタンス内の装置照会と書き込みはすべてキューで順に実行し、未完了の照会と書き込みの重複を防ぎます。

ディスクを排他ロックした後、MMC で現在の profile、ディスク情報、フォーマット容量、トラック情報を読み取ります。空で未フォーマットの単層 BD-R SRM、先頭トラック開始 0、生の書き込み可能容量が全量存在することが必要です。不明、使用済み、フォーマット済みの配置は拒否し、総セクター数を自動で減らしません。UI の総セクター数は 2048 バイト単位で同じ要求長に換算され、UDF 接頭部、描画領域、末尾メタデータをすべて含みます。小さい手動容量でも指定したのと同じセクター数を書き込みます。

書き込み完了後にキャッシュをフラッシュし、トラックを閉じ、BD-R の finalize 機能 6 でディスクをファイナライズします。キャンセルは現在の装置コマンド終了後に有効になります。キャンセルや書き込み失敗時はキャッシュフラッシュと装置解放だけを可能な範囲で行い、未完成イメージを成功としてファイナライズしません。各ロック解除は成功して初めて完了とし、失敗項目を 1 回再試行して診断にエラーを残します。成功済みの対になるカウント操作は重複実行しません。ファイナライズ開始後はコマンド完了を待ちます。予備領域なしでは不良ブロック再配置用の容量がなく、中断したディスクへの書き込みは通常再開できません。

BD の実時間速度は書き込み装置が受領確認したコマンドから算出し、装置キャッシュの影響を含みます。ディスク上のレーザーの瞬間速度ではなく、最終成功にはキャッシュフラッシュとファイナライズの完了が必要です。4× の公称ユーザーデータ速度は 18 MB/s（1× = 4.5 MB/s）です。UI は 10 進 MB/s を使い、要求倍率を実スループットの代わりにはしません。自動モードは現在のディスクが報告した最低設定を選びます。

書き込み直前に装置が返した設定速度を記録し、設定値と実時間スループットを別に保持します。書き込み中は 10 秒ごとと最終ブロック後に診断ウィンドウを記録し、入力ストリーム読み取り時間（待機とコピーを含む）と WRITE コマンド時間（転送と装置待機を含む）を区別し、受領確認済みの平均速度も残します。低頻度ログは装置照会を増やさず、進捗や速度の鮮度規則を変えません。入力読み取り時間は生成スレッドの純粋な計算時間ではなく、コマンド時間だけでは USB 転送と物理書き込みを分離できません。

画像ストリーミングは最大 8 ワーカー、16 クラスター（1 MiB）の有界バッチを使い、計算完了後に元の順序で書き出します。組み込み 3T/6T しきい値マッピングとスクランブル XOR は整数 SIMD を使い、位置計算は元の精度を維持します。検証済みディスクパラメーターをバイトごとに再検査しません。不変ラスター画像では自動で並列化し、組み込み校正パターンはサンプリングがスレッドセーフであると明示します。カスタムのサンプリングコールバックは既定で逐次処理です。事前バッファーは一時的な速度差だけを吸収し、持続的な書き込みには選択した装置速度を上回る供給速度が必要です。

プロトコルとワークフローのテストは偽装置と 1024 セクター（2 MiB）の UDF ストリームだけを使います。全 12,219,392 セクターについては容量とジオメトリのメタデータのみを検証し、全ディスク ISO は生成しません。物理書き込みの結果は実ディスクでの検証が必要です。

実装の根拠：[Microsoft のデータ送信とコマンドタイムアウトのインターフェース](https://learn.microsoft.com/en-us/windows/win32/api/imapi2/nf-imapi2-idiscrecorder2ex-sendcommandsenddatatodevice)、[libburn の MMC 実装](https://dev.lovelyhq.com/libburnia/libburn/src/branch/master/libburn/mmc.c)、[libburn の書き込みタイムアウト](https://dev.lovelyhq.com/libburnia/libburn/src/branch/master/libburn/spc.h)。

## 検証範囲

自動チェックは 17PP/EDC/Reed-Solomon、完全 RUB 再生、画像マッピング、並列生成、ISO/UDF、4 GiB 超のファイル、逐次書き込みコマンド、描画範囲、サイドカー、キャンセルを対象にします。ディスク上の UDF テストは 1024 セクターのみで、各 ISO は最大 2 MiB です。大きなファイルのテストでは、まずスパース属性を有効化して検証し、4 GiB 超の論理入力ファイル（実割り当て 1 MiB 未満）を作り、データを検証して破棄するストリームに順に出力し、大きな ISO は書きません。実ディスク容量は数学的な検証のみです。実際の書き込み装置にはアクセスせず、実ディスクで見える明るさや極性を証明しません。
